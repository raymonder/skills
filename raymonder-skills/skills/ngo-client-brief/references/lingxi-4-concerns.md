# 灵析 4 大关注点 · 核查清单

每次做简报，按这 4 个维度逐项核查。顺序固定，不要跳。目的是让 Raymond 在会议前 30 秒就能定位最强攻击点。

---

## ① 网络筹款

### 必查项

| 项目 | 怎么查 | 记什么 |
|---|---|---|
| 官网捐款页支付方式 | 机构官网「捐款 / 善業捐助 / 支持我們」页面 | 完整列出支持的方式（现金、支票、银行入数、信用卡、FPS、PayMe、Alipay HK、WeChat Pay、BOC iService 等） |
| 月捐 / 定期扣款 | 同页面搜「月捐 / 每月 / 定期 / 恒常支持 / monthly」 | 有无月捐入口，提交流程是纸质 or 电子 |
| 电子收据 | 同页面搜「收據 / receipt / 電子 / email」 | 是纸质邮寄还是电子发送（IR 876 报税表的格式问题） |
| 捐款人账户 | 查是否有「登录 / 会员中心 / my donation」入口 | 有无账户登录、是否能查历史捐款 |
| 卖旗日历史 | 搜「机构名 + 卖旗」或 `hkngolist.com` | 过去 3 年的日期 + 分区（港岛 / 九龙 / 新界） |
| 公开筹款活动 | 搜机构 Facebook / 活动页 | 最近一年的筹款活动类型和规模 |

### 关键判断

- **只有 <5 种支付方式** = 网络筹款是重大缺口，可作为主攻击点
- **没有月捐** = 灵析月捐模块就是最直接的 ROI 证明
- **电子收据纸质邮寄** = 极低挂果——提个捐款就要邮寄一张纸，成本远高于收益
- **有卖旗日但无线上配套** = 明确的时间窗筹款机会

### 估算公众筹款占比

公众筹款（不含政府拨款、基金会捐款）在总收入占比：

- **健康水平**：20–40%（如乐施会 / 东华三院等头部）
- **偏低水平**：10–20%（依赖政府拨款的中型 NGO）
- **严重偏低**：<10%（大多数传统宗教/地缘团体）

**怎么估算**：翻年报看「Donation from Public」「公眾捐款」「善款收入」这几栏；若机构有独立的「弘法账目」「募捐账目」不公开，**只能用推估**，在简报里用「似乎」「初步估算」标注。

## ② 会员管理

### 必查项

| 项目 | 怎么查 | 记什么 |
|---|---|---|
| 会员登录入口 | 官网首页和顶部 nav | 有 / 无；若有，点进去看需要什么字段 |
| 会员注册页 | 搜「加入 / 註冊 / 成為會員」 | 注册方式（纸质、电子、需要推荐人、需要审核）、会费金额 |
| EDM 订阅 | 官网底部 footer | 有无 newsletter signup |
| 义工登记 | 搜「義工 / volunteer」栏目 | 注册流程、有无线上表单 |
| 服务使用者档案 | 在 Service Center 页面 | 服务登记流程、是否要求个人资料 |

### 关键判断

- **没有会员登录** = 会员管理停留在 Excel / 纸质
- **会员数口径** = 要区分「宗教成员 / 荣誉会员 / 活跃捐款会员 / 服务使用者」——不同口径差一个数量级
- **义工是否有平台** = 卖旗日 / 大型活动需要几百义工，若靠 Excel + 电话，就是明确痛点

### 对佛教 / 道教 / 天主教机构的特殊注意

**不要把「宗教信众」等同于「CRM 会员」**。宗教成员有身份敏感，机构本身也不一定想把他们纳入数据库管理。安全切入：
1. 先做「捐款人档案」（不涉宗教身份）
2. 再做「义工登记」
3. 最后才是宗教成员登记——这一层很多机构根本不想碰

## ③ Service Center

### 必查项

| 项目 | 怎么查 | 记什么 |
|---|---|---|
| 中心数量 + 类型 | 机构官网「服務單位 / Services」栏目 | 全部列出，包括安老院 / 长者中心 / 青少年中心 / 幼儿园 / 特殊学校 / 诊所 / 庇护工场 / 职训 等 |
| 各中心主管 | 中心详情页 | 主管姓名（通常中心详情页底部有「主任 / 中心主管」字样） |
| 各中心服务范围 | 中心详情页 | 服务对象、服务类型、与其他中心是否有重叠 |
| 中心数码化 | 各中心的线上 presence | 有无独立网站 / 独立 Facebook / 线上报名 / 家属 app |
| 中心层面财报 | 社署 iConnect 或单个中心页面 | 有些大型中心会单独出财报 |

### 关键判断

- **7 个以上中心 + 无统一管理系统** = 灵析「多中心统一 + 独立运作」是完美匹配
- **中心独立财报各自审计** = 决策层在中心而非总会，销售周期会更短
- **各中心主管职级相同** = 见面对象职级在中心主管之上的可能性高
- **主管名字差异大** = 各中心历史独立招聘、文化差异大，销售时要让中心试点不要一刀切

### 和见面对象职级推测

香港社福 NGO 典型层级：
```
董事局 / 理事會
 └─ 總幹事 / Executive Director
      └─ 高级经理 / 助理总监 / Assistant Director
           └─ 服務經理 / Service Manager  ← 通常管 1 条 portfolio 的几个中心
                └─ 中心主任 / Centre-in-Charge  ← 管 1 个中心
                     └─ 社工 / 前线员工
```

**服务经理**通常管几个中心，不统管整个社福板块。确认 portfolio 范围是会议第一个必问问题。

## ④ 年度收支

见 `financial-extraction-workflow.md` 的详细提取流程。

### 关键判断

| 信号 | 含义 | 销售动作 |
|---|---|---|
| 盈余 >5% 总收入 | 预算宽裕 | 可推中间版或高级版 |
| 盈余 <2% 或亏损 | 紧缩 | 推基础版 + 试点中心 |
| LSG 占比 >80% | 高度依赖政府 | 攻「自筹能力不足」痛点 |
| LSG 占比 50-70% | 平衡型 | 攻「效率提升」痛点 |
| 专项津贴今年消失 | 断供 | **重要切入点** — 「这笔钱要补回来」 |
| Salary 占比 >80% | 人力密集 | 「释放员工时间」价值主张 |
| Stores 同比翻倍 | 可能数码化投入 | 现场顺势问 |

## 四大关注点综合 ROI 话术模板

在简报 1.6 节，用以下模板组装一句会议现场可直接念的话：

```
「<机构名>你們社福板塊 <财年> 有 HKD X 萬收入，
其中 Y% 是社署 LSG——這塊政府給了很穩。
但公眾籌款 <似乎/初步估算> 只佔 Z%，
跟其他同體量 NGO 差了 W 個百分點。
<特殊信号，如津贴断供 / Stores 翻倍>——
自籌這塊遲早要頂上來。
我查了政府 e-Procurement 和科技券，
貴會 <IT 投入现状>，
估計每年數碼化投入約 HKD A–B 萬，
跟同體量差了 C–D 萬。
靈析這個系統最直接的價值就是
把 Z% 做到 2Z%——每年多 E 萬現金流，
不用再向社署要。」
```

填空时务必用真实数字，不要留 `<>` 在输出里。

## 灵析套餐选型速查

| 机构条件 | 推荐起点 | 理由 |
|---|---|---|
| 单中心 / 小型 NGO（年收入 <1000 万） | 基础版 | 不要过度卖 |
| 多中心（3+）· 盈余健康 | **中间版** | 月捐 + 多支付 + 分权，ROI 最快 |
| 超大型 umbrella（10+ 单位） | **中间版起 + 单中心试点** | 不要一上来推高级版，先赢一个中心 |
| 已有自建 CRM | 高级版 | 迁移成本高，要一次到位 |
| 宗教机构 | **中间版 + 长周期** | 理事会 + 宗教敏感，3–6 个月成单 |
