# 会前简报生成

为灵析（Lingxi）CRM/SaaS 产品的销售前置工作服务。核心是把公开情报转成一份 Raymond 在会议前 30 分钟能速读、会议中能随手翻、会议后能回灌的作战文件。

## 核心原则

> **最重要的一条**：简报质量 = **数字 × 解读**。没有数字就是空话，有数字没解读就是数据库。**每一个数字后面都要紧跟一句「所以⋯⋯」**。这是 insight 型简报与流水账型简报唯一的分水岭。

1. **先锚定灵析 4 大关注点，再做机构扫描**。简报不是百科全书——它是一份销售武器。如果某段内容跟「网络筹款 / 会员管理 / Service Center / 年度收支」这 4 件事无关，砍掉或缩到最短。
2. **用真实数字开场**。财报 OCR、卖旗日历史、员工数估算——这些具体数字让客户一眼看出 Raymond 做过功课。推测值要用「似乎」「初步估算」开头，不要假装硬数据。
3. **识别「两本账」**。香港宗教型 umbrella NGO 通常社福板块（受社署监管、有公开财报）和弘法/总会板块（私账、不公开）是分开的。见面对象管哪本账决定你能讨论什么数字。**对 umbrella NGO，官网「关于我们」页通常会披露一个整体经费数（例如"13 亿"），而 AFR 只是 SWD 资助部分（例如 746M）——两个数字都要写上，并注明分别属于哪本账**。
4. **报告末尾不要自评**。不加「这份简报做得怎么样 / 评分 X/10 / 做得好的地方 / 仍偏弱」这类总结段。Raymond 只想看干货，他会自己判断。
5. **会议作战用提示式，不用时间块**。不要写「0–5 min 做 X，5–20 min 做 Y」——现场节奏会变，时间块反而制造焦虑。用 `> 提示` 标注关键注意点即可。
6. **每个数据点都要带一行 "so-what"**。这是 insight 与罗列数据的最大分水岭。「LSG 占 72%」本身不是 insight，「LSG 占 72% → 政府饭稳但公众筹款这块弱 → 灵析帮他们把公众筹款从 5% 推到 10% = 每年多 3,700 万」才是 insight。**看到数字不做解读 = 写了等于没写**。
7. **时间节点必须变成限期钩子，不只是日历事实**。看到卖旗日、财年截止、筹款高峰、系统换期这类日期，立刻问：「离今天还有几天？能不能作为『免费先接』『小范围试点』『xx 日前数据可用』的钩子？」**每一个日期都要至少带一个销售动作钩子**。例：「2026-05-09 卖旗日还有 17 天 → 提『卖旗日免费先接』作为进门筹码」。
8. **执委会成员 = 决策逻辑档案**。必查「理事会 / 执委会」页面，列出关键成员的职业背景（银行家 / 医生 / 律师 / 学者 / 教会 / 企业家），然后一句话推断决策模式：
   - 财金精英主导 → 企业化 ROI 逻辑，要竞品对比 / SLA / 退出条款
   - 教会 / 宗教人士主导 → 信念式，mission-first 框架
   - 学者 / 政界主导 → 合规式，要政策引用 + 数据合规说明
   - 混合型 → 温和平衡，需要复合话术
9. **报价永远不给三档菜单**。对高职级买家（高级经理 / 总监 / 副总干事以上），**直接锚定推荐档位**，配一句日常化对标（「等于你团队某位高管的 X 天工资」「等于一次印刷品的 X 折」）。三档并列会把决策难度甩回给客户，让成单周期翻倍。
10. **盘点现有数码化不要当空白**。**先查**机构有没有自研 / 自运营的数字项目（如 CharityToday、eldercare App、Salesforce NPC、CiviCRM），以及子域名站点（`cc.xxx.org.hk`、`rs.xxx.org.hk`、`flagday.xxx.org.hk` 这类服务线独立站）。**永远不要把灵析定位成"替代现有系统"，总是定位成"把散落的拼接起来" / "补齐剩余缺口"**。对方已有的数字化建设看作加分项，不是障碍——**看不见就是漏做功课**。

## 5 阶段工作流

按顺序执行，每个阶段的产出直接喂给下一个阶段。不要跳阶段——跳了就容易出泛泛的内容。

### Phase 1 · 机构基本面侦察

拉一份简版机构画像。只用以下字段，不要扩写：
- 全称 · 英文名 · 成立年份
- 性质（是 Section 88 慈善 / 有限公司 / 宗教团体 / 其他）
- 规模口径（会员多少 / 员工多少 / 会属单位多少 / 服务点多少）
- 现任最高负责人（理事长 / 会长 / 总干事）
- 总部地址 · 电话 · 官网
- **执委会 / 理事会关键成员**（至少主席 + 副主席 + 司库 + 任何挂着主教 / 会督 / 医生 / 法官 / 银行家头衔的委员）—— 必查！官网路径通常是 `/about/associate.php` 或 `/about/council.php` 或 `/关于我们/理事会`
- **决策逻辑判定**（一行）：根据执委会成员背景组合，给出一句「这是财金精英俱乐部 / 教会系 / 学者型 / 混合型」，以及对应的销售语气指引

**数据源优先级**（详见 `references/public-data-sources.md`）：
1. 机构官网（通常有「关于我们」或「组织架构」页）
2. 维基百科（快速查出成立年 / 前任负责人）
3. HKCSS NGO 数据库 `ngo.hkcss.org.hk`
4. HKNGO 目录 `hkngo.hk`
5. 社署 iConnect 若机构受助的话

> 见面对象（联系人）单独查一次——LinkedIn、新闻、Facebook。HK NGO 中层经理通常**零公开足迹**，查不到是常态，不要硬凑。
>
> **但如果是高级经理 / 总监及以上级别**，一定要找到至少一条公开线索——LinkedIn summary / 他参与的项目新闻稿 / 机构领导团队页的头衔描述。这一层级零公开足迹的概率很低，找不到往往是没搜对关键字。

### Phase 2 · 年度收支数据抓取（最重要）

**凡是受社署资助的 NGO**（大约港 NGO 的 60-70%），都必须在官网公开发布《Annual Financial Report for Social Services Units Subsidised by SWD》这份 PDF。这是你能拿到的最硬的数字。

具体怎么找、怎么 OCR、怎么提取关键数字，见 `references/financial-extraction-workflow.md`。

> **⚠️ 硬规则：OCR 不是可选项。** 如果 PDF 是扫描版，WebFetch 拿不到文字——**不能说「PDF 为扫描版，未能提取」然后跳过**。必须走 `pdftoppm -r 300 + tesseract -l eng` 的 OCR 流程，一页一页把关键数字抠出来（英文单语言包就够，财报账目名都是英文）。**放弃 OCR = 放弃整份简报最重要的弹药**。详细命令见 `references/financial-extraction-workflow.md` Step 3。

**必须提取的数字**：
- 总收入 · 总支出 · 本年度盈余
- LSG 整笔拨款（含 PF）· 占总收入百分比
- 服务收费 Fee Income
- 中央项目拨款（如有，注意同比变化——津贴断掉是重要信号）
- 薪酬 + 公积金 = 人事成本 · 占总支出百分比
- 其他支出细目（水电、食物、维修、活动、保险、**Programme Expenses 活动、Administrative Expenses 行政、Stores and Equipment 商店及设备**）
- 每一个细项的**同比变化百分比**（当年 vs 上年）
- 薪酬分段分布里**年薪 >HKD 100 万的岗位数**（在 Personal Emoluments 附录里，反映高管密度）
- **LSG 储备 / 准备金**（Reserve）总数——通常以定存形式持有，反映可动用现金

**同比变化是关键销售信号**，且每条必须配一句 so-what：
- **Admin Expenses +50% 以上** → 很可能在做系统升级 / 外包服务 / 办公重装 → 当下有预算
- **Stores and Equipment +30% 以上** → 硬件采买扩张，IT 硬件投入的可能性大
- **Programme Expenses 翻倍** → 项目规模扩张，对应可能有新的指定用途拨款
- **Other Income 里"Other Funds or Donations for Designated Purposes" 从 0 或小额突增到千万级** → **异常信号**，必须现场问清楚是哪个金主 / 什么项目 / 是否允许数字化支出
- **Central Items 某笔专项消失** → 津贴断供，机构需要自筹补上，灵析筹款工具有机会
- **LSG 增长 >10%** → 扩张年份，预算松
- **盈余翻倍以上** → 储备充足，敢花钱

**填进简报的规矩**：不是把数字填进表格就完事，每张表下面必须有一个「同比关键变化」子段，把上面 6 类信号中命中的 2-3 条挑出来讲解。

### Phase 3 · 灵析 4 大关注点侦察

按固定顺序处理，每块都要有具体结论，不要泛泛讲。逐项核查清单见 `references/lingxi-4-concerns.md`。

**① 网络筹款**：
- 官网「捐款 / 善业捐助 / 支持我们」页面，逐项列出支持的支付方式
- 明确标注**缺失的方式**（信用卡 / PayMe / FPS / 月捐 / 电子收据 / 捐款人账户）
- 估算公众筹款占总收入百分比（财报里查或用总会捐款栏目）

**② 会员管理**：
- 官网有无会员登录入口 / 会员注册页
- EDM 订阅入口
- 义工登记平台
- 捐款人账户

**③ Service Center**：
- 中心数量 · 类型（安老院 / 长者中心 / 青少年中心 / 幼儿园 / 特殊学校 / 职业训练 / 等）
- 各中心是否有独立主管 · 列出主管名字
- 中心层面的数码化（线上报名 / 家属 app / 排班系统 / 服务记录系统）

**④ 年度收支**：用 Phase 2 提取的数字填

### Phase 4 · 附加数据

这一节是 Raymond 明确点名要的补充数据点：

- **月捐**：官网有无月捐入口 / 是否有任何「每月支持」「定期奉献」功能
- **卖旗日**：搜「机构名 + 卖旗」或 hkngolist.com，列出过去 3 年的卖旗日期 + 分区。按社署规则 3 区（港岛 / 九龙 / 新界）轮转，可推测下次
- **Facebook 动态**：专页活跃度、发帖内容类型（活动 / 公告 / 法会 / 筹款）
- **会员数 / 员工数估算**：员工数可用 `薪酬总额 ÷ 香港社福前线平均年薪（35-45 万）` 粗估
- **社署拨款金额**：来自 Phase 2 的 LSG 数字

### Phase 5 · 数码化投入侦察

这块分两步：**先盘点已有，再估算缺口**。顺序不能反——直接跳到"估算缺口"会把客户已有的数字化建设当成空白，犯职业级错误。

#### 5.1 先盘点已有数字化（必做 · 不能跳）

查以下 5 类信号，每类都要给出「有 / 无 / 未查到」的明确结论：

1. **机构自研 / 自运营的命名项目** — 在机构官网搜「平台 / 系統 / App / Digital / 科技 / tech」，新闻稿里经常有（例：「XX 搜望·相助」「YY Charity App」）。如果找到，记录：项目名 · 启动年份 · 资助方 · 已产生的数据点（如发放善款总额、用户数）
2. **子域名站点** — 各服务线是否有独立站点（`cc.xxx.org.hk` / `rs.xxx.org.hk` / `flagday.xxx.org.hk` 等）。多子域 = 机构已经有数字化分化但没有统一后台，是灵析**最硬的切入论点**
3. **官网招聘版块** — 近 3 个月在招岗位里有没有 IT / 系统 / 数码化 / Digital / Innovation 职位；若**零个**，说明他们倾向**外部采购而非自建团队**（✓ 利好灵析）
4. **政府 e-Procurement / GLD e-Tender Box** — 搜机构名是否有 IT 招标记录
5. **创新科技署科技券 TVP 批核名单** — 搜机构名是否申请过（机构体量大者通常不适用，但要确认）

#### 5.2 再估算数字化总投入 + 缺口

从财报 Other Charges 里抠数字：
- Administrative Expenses（通常含 IT 外包 / 订阅 / 办公系统）
- Stores and Equipment（含 IT 硬件）
- 按内部比例拆分估算 IT 占比

或按同体量 NGO 类推估算：
- 硬件（PC / 打印机 / 路由器）：每中心 2–4 万 / 年
- 软件（MS Office / 反毒 / 云盘）：3–8 万 / 年
- 网站 / 邮件托管：2–5 万 / 年
- 项目专项（自研系统维护 / 专用平台）：依机构体量 50–300 万 / 年

**然后对比**：同体量 NGO 通常占总支出 **1–2%**。机构当前估算值占 X%。
- 如果当前 <1%：**缺口大 + 需求高**，激进报价
- 如果当前 1–2%：**已在投入轨道**，灵析是增补，用渐进报价
- 如果当前 >2%：**已是数字化先行者**，要从「整合 / 替代碎片化 / 提升 ROI」角度切入

**不要统一说"缺口 X–Y 万"**——根据当前水平给出不同的定位话术。

#### 5.3 Phase 5 产出要放进简报 1.5 节

简报的 1.5 节必须包含两个子块：
- 「**已有数字化盘点**」（项目名 + 子域名 + 职位 + 财报 IT 账目——逐项列出）
- 「**缺口估算 + 话术定位**」（按 5.2 的三档分类选一条）

### Phase 6 · 组装简报

**严格按 `templates/brief-template.md` 的固定结构输出**。具体注意：

- **不加自评模块**。不要在尾部写「这份简报做得怎样」「评分多少」「做得好的地方」「仍偏弱的地方」。Raymond 明确不要这种尾部。

- **作战计划用提示式**。不用「0–5 min / 5–20 min」这种时间块。用 5 段结构（开场 / 听他讲 / 演示 / 价格 / Close），每段配一行 `> 提示：`。

- **报价段按"锚定高档 + 生活化对标"格式**。**不列三档并列**。格式固定为：
    ```
    ❌ 不直接说"我们有基础 / 中间 / 高级"
    ✓ "以你们的体量——<具体的客户规模数字>——只有<推荐档位>能配齐<3 项功能>。
       年费 HKD X 万，<合约条款 / 折扣安排>。
       这个价格对你们<生活化对标：等于某位员工的几天工资 / 一次印刷的几折 / 一笔小额捐赠>。"
    > 提示：报完价停 3 秒。
    ```

- **红线按「触发 + 应对 + 原因」三要素格式**。**不只列"不要谈某话题"这种大类禁令**。每条红线必须写清楚：
    1. **触发场景**：什么时候会踩到这条线（对话里出现什么信号）
    2. **具体应对**：那一刻 Raymond 要做什么 / 说什么
    3. **背后原因**：为什么这条会踩雷
  
  红线只列 **3 条真正非显而易见的**。Raymond 自己会避的（不叫捐款人客户、不说系统落后、尊重创办人等）**不要占名额**。应该选：**推测值被挑战时的改口话术** / **执委会背景引发的特殊话术禁区** / **两本账不混讲** / **宗派身份不要硬套** / **现任 vs 前任敏感话题**——按机构性质选 3 条。
  
  示例红线格式：
  > **红线 2**：执委会里是 XX 银行系统的人 → 不要用"因为帮助老人家我们特别便宜"这种情感话术 → 理由：财金背景的董事看 ROI 数字，情感话术在他们眼里是减分项。

- **资料来源列 6-10 条**。不是越多越好，列他可能翻回去查的那几条。
- **0 节（一页纸速览）必须回答"为什么这一家 Fit 高 / 低"**。不是罗列 8 个字段的数据，是给出一句整合判断。其中「最佳进攻时间窗」和「今天必须带走的 3 个答案」两栏**最能体现 insight 密度**——务必具体到「17 天后卖旗日」「88M 指定拨款是什么金主」这种级别。

## 输出位置

简报文件保存到 `/sessions/lucid-stoic-ride/mnt/个人抽取-客户信息/会前简报-<机构名>.md`，然后给 Raymond 提供 computer:// 链接。

## 三个高价值应用场景

- **首次拜访 NGO 客户前 1-2 天**（主要场景）：按 5 个 phase 完整做一遍
- **会后 30 分钟回灌**：把简报第 5 节「会后必做」表格填满，下次同类机构可直接复用模板
- **批量筛客**：如果 Raymond 一次给你 5-10 个机构名，先只跑 Phase 1 + Phase 2 + Phase 3 速扫，按 Fit 评分排优先级，再对最高分的 2-3 家做完整简报

## 何时追加、何时砍减

- **加**：如果 Raymond 提到特定担忧（例如「这家最近有丑闻」「这家是天主教背景」），在现有结构里加一行定向侦察，不要新增段落
- **砍**：对小型机构（年收入<1000 万），Phase 5 的数码化侦察可省略——他们的数码化本身就不成话题，浪费笔墨

## 两个绝对不要做的事

1. **不要拿推测值当硬数据讲**。公众筹款占比、数码化投入估算、员工数估算——这些都要用「初步估算 / 似乎 / 推估」开头。客户一句「我们实际上不是这样」你要能立刻接受并转向。
2. **不要在简报末尾加自评**。这是 Raymond 明确的反馈。他自己会判断这份简报对他有没有用。
