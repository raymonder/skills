# 卖旗 / e-Flag Day Playbook（mode 3）

> 香港賣旗日方法論。80% 篇幅在 **e-Flag**（電子賣旗），20% 在傳統卖旗作背景。
> 引用詳見 `evidence-base.md` 和 `research/03_賣旗e-Flag證據基.md`。

## 核心定位

e-Flag **不是 COVID 應急方案**，而是把 HK NGO 的物理動員力量（最大個案 17,000 義工，保良 2025）× 615 萬社交用戶的線上分享網絡（Digital 2025 HK），做槓桿轉換的長期基建。目前主流平台都只做到「募款」沒做到「培育」（資料回流 CRM、後續月捐轉化）——這是切入點。

## 監管硬約束（不能 work around）

1. **公開籌款許可證 PSP** 由社署署長根據《簡易程序治罪條例》發出。
2. 兩類賣旗日：**全港**（同一日全港只一機構獨享）+ **分區**（同日港島 / 九龍 / 新界各一機構各據一區）；一年共 **56-58 個賣旗日**（2025-26 年度 56 日）。
3. 賣旗時段：**07:00–12:30**（街頭）；線上 **可全天接受捐款**（許可證內覆蓋）。
4. 申請門檻：非牟利 + IRD section 88 + **過去 3 年持續舉辦慈善活動**。
5. **行政費上限 10%**——所有賣旗相關成本（旗紙、義工、平台、保險、印製）合計不可 > 籌得總額 10%。**e-Flag 平台費用也計入這 10%**。
6. 申請週期：**4-5 月開放 → 9-10 月通知 → 11 月揀日 → 12 月正式發 PSP**——比公眾日提前 6-12 個月。
7. 必須提交獨立核數師收支結算表，公布機構網頁 + 社署 data.gov.hk。

**對機構財務的含意**：e-Flag 工具費用都計入 10% 封頂內。所以平台採購要算「省下的義工 / 印製 / 點算成本是否抵消平台費」——目標是把每塊錢的 90% 留給慈善服務。

## 12 週 e-Flag 籌備時間線

```

W-11 ┃ 主題與口號定稿；設計旗紙 + 旗袋 + 金旗

W-5  ┃ 學校 / 企業批量開隊（透過 Social Career 等義工平台引流）
W-4  ┃ 訂購實體旗袋、印 QR；按社署規定培訓義工
W-3  ┃ 公關 / 媒體稿；KOL / 校長 / 藝人短片；金旗大客洽談
W-2  ┃ 中段衝刺：排行榜公布、PK 賽、企業配捐
W-1  ┃ 衝刺週：限時翻倍配捐、IG 直播倒數、社署最後資料核對
D-0  ┃ 賣旗日當天（07:00–12:30 街頭 + 全天線上）；現場 QR 旗袋；實時排行榜直播
W+1  ┃ 結算：旗袋點算（Flag-Bag Easy）、線上對帳、排行榜封榜
W+2  ┃ 致謝：每位義工 / 捐贈者個人化感謝信、電子證書、感謝短片

W+4  ┃ 收支結算表初稿 → 核數師 → 社署 + 機構網頁公開
```

## e-Flag 核心機制 6 件套

1. **個人 / 團體電子旗袋（e-Flag Bag）**：每義工 / 隊伍註冊後自動生成獨立連結 + QR Code。
2. **多渠道一鍵分享**：WhatsApp 第一順位（HK 滲透 74.7%）、Facebook 第二（73.5%）、IG Story 第三、Email / WeChat。
3. **實時排行榜**：個人、團體、企業、最具動員力團隊四類。
4. **獎項激勵**：網上籌款大獎（個人 / 機構）+ 最具動員力團隊 + 企業籌款獎。
5. **金旗（Gold Flag）大額認捐位**：HK$300-500 起一檔，附鳴謝刊登 + 限定版實體紀念旗——主募款額外加碼。
6. **線下混合 QR**：街頭義工旗袋印 QR Code，路人可掃碼以電子付款代替投幣（適應 65.6% 用過手機支付的現實）。

## 主流平台 4 類對比

| 類別 | 代表 | 優勢 | 劣勢 |
|---|---|---|---|
| 平台型線上募款 | **SparkRaise**、SimplyGiving | 自助 + 抽 tip 制即裝即用 | **無 CRM 後端**、資料留在平台 |
| 賽會 / 旗袋 SaaS | **HKCSS Flag-Bag Easy** | HK 社聯出品、App 點算 QR 旗袋 | 偏旗袋管理、非募款主流程 |
| 機構自建 | 紅十字、公益金、保良、東華、AVS | 完全品牌掌控 | 開發成本高、IT 維護 |
| CRM + 募款一體 | **灵析** / DonorPerfect / Salesforce NPSP | 同步月捐 + 自動發收據 + 後續培育 | 學習曲線 / 配置投入 |

**HK 中型 NGO 痛點**：用 SparkRaise 解了募款，但**捐款人資料困在 SparkRaise，回流 CRM 靠人手 Excel**——這就是 灵析 的明確機會。

## 後續轉化（一次性 → 長期）

賣旗最大未開採價值不是當天，是 **W+3 開始的轉化窗口**：

### 4 種典型做法
1. **金旗 / 大額捐贈者特別流程**：賣旗後 7 天紙本 + 電郵雙軌寄出限定紀念旗 + 通訊書 + 月捐邀請。
2. **隊長 / 義工反向轉化**：隊長轉長期支持者率 > 一次性捐贈者；30 天為「隊長月捐轉化窗口」。
3. **電子收據自動發送**：HK$100+ 捐贈在 14 日內收到含 IRD 編號收據——這封郵件天然承載二次轉化文案空間。
4. **賣旗日專屬會員身份**：保良局、紅十字、公益金都邀請大捐贈者進「主席會 / 名譽會員」榮譽體系。

### KPI 對照

| 動作 | 健康值 |
|---|---|
| W+2 個人化致謝信完成率（所有捐贈者）| 100% |
| W+3 大額捐贈者 1-on-1 接觸完成率（金額前 5%）| 100% |
| W+4 收支結算表初稿提交核數師 | 100% |
| 賣旗一次性 → 月捐轉化率（30-90 天窗口）| 5-15% |
| 隊長 → 月捐 / 長期義工轉化率 | 20-40% |

## 動員的 4 大 HK 場景

1. **聯校 / 校友會**：HK 中學生「義工時數」幾乎成升學申請標配。賣旗日是少數一次過拿 5-6 小時 + 證書的機會——校網是 e-Flag 最大流量池。
2. **企業 CSR**：上市公司內部 Workplace / Teams 推賣旗隊 + dollar-matching。
3. **賽馬會基金生態**：HKJC 慈善信託基金資助大量 NGO，其資助機構參與賣旗自帶傳媒曝光 + 義工網絡。
4. **家長 / 校友 WhatsApp 群組**：HK 家長 WhatsApp 群滲透極高，「一個校友媽媽轉發 = 一晚 5-10 萬」的隱形渠道。

---

## 不要做

- 把 e-Flag 當「線上替代街頭」——HKFHY 2020 純線上後籌款額大幅下跌，混合才是強的。
- 在 W-6 才開始招企業 CSR 配對——3 個月起跳的合約週期。
- 平台選擇上忽略「資料回流 CRM」這條——錯過 W+3 轉化窗口。
- 用 18 歲以上義工為唯一陣型——校網義工才是 HK 賣旗的真正引擎。
- 把獎項設計得太複雜（>3 大類）——複雜獎勵反而 disengage 義工。

## 灵析在 e-Flag 的工具支持

- W-10：e-Flag 募款頁拖拉建頁 + 個人 / 團體頁自動生成 + QR Code 一鍵生成。
- W-8：實時排行榜 + 金旗版面 + 隊伍邀請流程 token-link。
- W-5：隊長 onboarding kit 模板（WhatsApp / IG / 海報）+ 批量隊伍管理。
- D-0：實時排行榜直播 + 現場 QR 旗袋 + 線上線下對帳。
- W+2：每位義工 / 捐贈者個人化感謝信自動觸發。
- W+3：賣旗捐贈者資料 **自動回流 CRM** → 月捐邀請自動派發；隊長標籤 + 後續培育序列。
- W+4：收支結算表自動匯總（捐贈金額、行政費、義工人手成本）+ 一鍵生成核數師對齊格式。
